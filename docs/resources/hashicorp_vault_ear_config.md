# yba_hashicorp_vault_ear_config (Resource)

Manages a YugabyteDB Anywhere encryption-at-rest configuration that uses a key of the HashiCorp Vault transit secrets engine as the master key. YugabyteDB Anywhere uses the key to wrap and unwrap the universe keys of each universe that uses the configuration.

Point the configuration at an existing transit key with `key_name`, or let YugabyteDB Anywhere create the key. Terraform does not manage or delete a key that YugabyteDB Anywhere creates.

There are two authentication modes. Set `token` to authenticate with a Vault token, or set `role_id` and `secret_id` to log in with the AppRole auth method at `auth/approle`.

~> **Security Note:** `token` and `secret_id` are stored in the Terraform state file and marked sensitive. Use a secure state backend and restrict access to state files.

~> **Note:** Only the arguments whose description says so can change in place, and Terraform ignores a change after creation to the arguments whose description says that. A change to any other argument forces replacement. YugabyteDB Anywhere does not delete a configuration that a universe has used: it keeps the universe's key history, also after encryption is disabled or the universe moves to another configuration, until the universe is deleted. A destroy of such a configuration fails, and the error names the universes. To move universes to a new configuration, create it, change `encryption_at_rest.kms_config_uuid` on each universe, and keep the old configuration (or remove it from state) until its universes are deleted. Give the new configuration `depends_on` on the old one, so that `terraform destroy` deletes the universe before the old configuration.

~> **Note:** Terraform refreshes `in_use` and the non-secret settings. YugabyteDB Anywhere masks credentials, so a credential changed outside Terraform, for example in the YugabyteDB Anywhere UI, does not show as drift. An apply sends a credential again only when the credential or the authentication mode changes.

Use the configuration in a universe through its `encryption_at_rest` block. The
[Encryption at Rest](../guides/universe-edit-actions.md#encryption-at-rest) section of the
Universe Edit Actions guide describes how to enable encryption, rotate the master key or the
universe key, and disable encryption. For the Vault setup, and a sample policy for the token or
the AppRole, see
[Create a KMS configuration using HashiCorp Vault](https://docs.yugabyte.com/stable/yugabyte-platform/security/create-kms-config/hashicorp-kms/).

## Example Usage

```terraform
# Encryption-at-rest configuration on a key of the Vault transit secrets
# engine, with a Vault token for authentication. When the key does not exist,
# YugabyteDB Anywhere creates it.
resource "yba_hashicorp_vault_ear_config" "token" {
  name          = "vault-prod"
  vault_address = "https://vault.example.com:8200"
  token         = var.vault_token
  mount_path    = "transit/"
  key_name      = "yb-master-key"
}

# AppRole authentication in a Vault Enterprise namespace. The mount path
# starts with the namespace.
resource "yba_hashicorp_vault_ear_config" "approle" {
  name           = "vault-central"
  vault_address  = "https://vault.example.com:8200"
  role_id        = "8f5ec0a3-6a1f-4d0e-9a52-2d6c3f1b7e44"
  secret_id      = var.vault_secret_id
  auth_namespace = "yb"
  mount_path     = "yb/transit/"
  key_name       = "yb-master-key"
}

# A universe uses a configuration through its encryption_at_rest block:
#
#   encryption_at_rest {
#     enabled         = true
#     kms_config_uuid = yba_hashicorp_vault_ear_config.token.uuid
#   }
#
# The yba_universe example shows a complete universe with the block.
```

## Schema

### Required

- `name` (String) Name of the configuration. Must be unique per customer. YugabyteDB Anywhere cannot rename a configuration, so a change forces replacement.
- `vault_address` (String) Address of the Vault server, for example `https://vault.example.com:8200`. YugabyteDB Anywhere connects to it directly. A change forces replacement.

### Optional

- `auth_namespace` (String) Vault Enterprise namespace of the AppRole auth method. Requires `role_id`. `mount_path` must then start with the namespace, for example `ns1/transit/` for the namespace `ns1`. Can change in place.
- `key_name` (String) Name of the transit key. This key is the master key. YugabyteDB Anywhere creates it when it does not exist. Defaults to `key_yugabyte`. A change forces replacement.
- `mount_path` (String) Mount path of the transit secrets engine, ending with `/`. Defaults to `transit/`. A change forces replacement.
- `role_id` (String) Role ID of the AppRole. Set it with `secret_id` instead of `token`. Can change in place.
- `secret_id` (String, Sensitive) Secret ID of the AppRole `role_id`. YugabyteDB Anywhere logs in with it each time it uses the key, so create it with no use limit, and change it before it expires. Can change in place.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))
- `token` (String, Sensitive) Vault token. Set it, or set `role_id` and `secret_id`. Can change in place: YugabyteDB Anywhere first checks that the new credentials can decrypt the active universe key of each universe that uses the configuration.

### Read-Only

- `id` (String) The ID of this resource.
- `in_use` (Boolean) Whether a universe holds key history for this configuration. A configuration in use cannot be deleted.
- `uuid` (String) UUID of the configuration.

## Import

Import a HashiCorp Vault configuration with its UUID. The `yba_ear_config` data source returns
the UUID for a configuration name:

```sh
terraform import yba_hashicorp_vault_ear_config.token <config-uuid>
```

Import fails for a configuration of another KMS provider, and the error names that provider.
Import reads every argument except `token` and `secret_id`. YugabyteDB Anywhere masks them when
it lists a configuration, so import leaves them empty. When the configuration sets `token` or
`secret_id`, the first plan after the import shows one in-place update, and the apply sends the
credentials from your configuration.
