# yba_azure_ear_config (Resource)

Manages a YugabyteDB Anywhere encryption-at-rest configuration that uses an Azure Key Vault key as the master key. YugabyteDB Anywhere uses the key to wrap and unwrap the universe keys of each universe that uses the configuration.

Point the configuration at an existing key with `key_name`, or let YugabyteDB Anywhere create an RSA key with that name. Terraform does not manage or delete a key that YugabyteDB Anywhere creates. An existing key must be an RSA key that is enabled, has no expiration date, has no activation date in the future, and permits the wrap key and unwrap key operations.

There are two authentication modes. Set `client_secret` to authenticate as the service principal `client_id`. Or leave `client_secret` unset to authenticate as the YugabyteDB Anywhere host through the Azure default credential chain, for example a managed identity of the Azure VM. In this mode, `client_id` is the client ID of the managed identity. The identity needs the key permissions Get, Wrap Key and Unwrap Key, and Create when YugabyteDB Anywhere creates the key. YugabyteDB Anywhere checks them when it creates or edits the configuration. After the key gets a new version, YugabyteDB Anywhere also needs List to unwrap the universe keys that an older version wrapped. With Azure RBAC on the key vault, the Key Vault Crypto User role grants Get, List, Wrap Key and Unwrap Key.

~> **Security Note:** `client_secret` is stored in the Terraform state file and marked sensitive. Use a secure state backend and restrict access to state files, or authenticate as the YugabyteDB Anywhere host, which keeps the secret out of Terraform.

~> **Note:** Only the arguments whose description says so can change in place. A change to any other argument forces replacement. YugabyteDB Anywhere does not delete a configuration that a universe has used: it keeps the universe's key history, also after encryption is disabled or the universe moves to another configuration, until the universe is deleted. A destroy of such a configuration fails, and the error names the universes. To move universes to a new configuration, create it, change `encryption_at_rest.kms_config_uuid` on each universe, and keep the old configuration (or remove it from state) until its universes are deleted. Give the new configuration `depends_on` on the old one, so that `terraform destroy` deletes the universe before the old configuration.

~> **Note:** Terraform refreshes `in_use` and the non-secret settings. YugabyteDB Anywhere masks credentials, so a credential changed outside Terraform, for example in the YugabyteDB Anywhere UI, does not show as drift. An apply sends a credential again only when the credential or the authentication mode changes.

Use the configuration in a universe through its `encryption_at_rest` block. The
[Encryption at Rest](../guides/universe-edit-actions.md#encryption-at-rest) section of the
Universe Edit Actions guide describes how to enable encryption, rotate the master key or the
universe key, and disable encryption. For the YugabyteDB Anywhere side, see
[Create a KMS configuration using Azure](https://docs.yugabyte.com/stable/yugabyte-platform/security/create-kms-config/azure-kms/).

## Example Usage

```terraform
# Encryption-at-rest configuration on an existing Azure Key Vault key, with a
# service principal for authentication.
resource "yba_azure_ear_config" "client_secret" {
  name          = "azure-kv-prod"
  client_id     = "00000000-0000-0000-0000-000000000001"
  client_secret = var.kms_client_secret
  tenant_id     = "00000000-0000-0000-0000-000000000002"
  vault_url     = "https://yb-prod-vault.vault.azure.net/"
  key_name      = "yb-master-key"
}

# Authentication as the YugabyteDB Anywhere host: no client secret in
# Terraform or in state. client_id is the client ID of a managed identity on
# the YugabyteDB Anywhere VM. When the key does not exist, YugabyteDB Anywhere
# creates it as an RSA key of key_size bits.
resource "yba_azure_ear_config" "managed_identity" {
  name      = "azure-kv-central"
  client_id = "00000000-0000-0000-0000-000000000003"
  tenant_id = "00000000-0000-0000-0000-000000000002"
  vault_url = "https://yb-central-vault.vault.azure.net/"
  key_name  = "yb-master-key"
  key_size  = 4096
}

# A universe uses a configuration through its encryption_at_rest block:
#
#   encryption_at_rest {
#     enabled         = true
#     kms_config_uuid = yba_azure_ear_config.client_secret.uuid
#   }
#
# The yba_universe example shows a complete universe with the block.
```

## Schema

### Required

- `client_id` (String) Client ID of the service principal when `client_secret` is set, or of the managed identity on the YugabyteDB Anywhere host when it is not. Can change in place.
- `key_name` (String) Name of the key in the key vault. This key is the master key. YugabyteDB Anywhere creates it as an RSA key of `key_size` bits when it does not exist and the identity has the Create permission. A change forces replacement.
- `name` (String) Name of the configuration. Must be unique per customer. YugabyteDB Anywhere cannot rename a configuration, so a change forces replacement.
- `tenant_id` (String) Azure tenant ID of `client_id`. Can change in place.
- `vault_url` (String) URL of the key vault, for example `https://my-vault.vault.azure.net/`. A change forces replacement.

### Optional

- `client_secret` (String, Sensitive) Client secret of the service principal `client_id`. Leave it unset to authenticate as the YugabyteDB Anywhere host. Can change in place: YugabyteDB Anywhere first checks that the new credentials can unwrap the active universe key of each universe that uses the configuration. Removing it switches the configuration to the host's identity.
- `key_size` (Number) Size in bits of the RSA key that YugabyteDB Anywhere creates: `2048`, `3072` or `4096`, and `2048` when not set. For an existing key, YugabyteDB Anywhere stores the value but does not compare it with the key. A change forces replacement.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `id` (String) The ID of this resource.
- `in_use` (Boolean) Whether a universe holds key history for this configuration. A configuration in use cannot be deleted.
- `uuid` (String) UUID of the configuration.

## Import

Import an Azure Key Vault configuration with its UUID. The `yba_ear_config` data source
returns the UUID for a configuration name:

```sh
terraform import yba_azure_ear_config.client_secret <config-uuid>
```

Import fails for a configuration of another KMS provider, and the error names that provider.
Import reads every argument except `client_secret`. YugabyteDB Anywhere masks the client
secret when it lists a configuration, so import leaves `client_secret` empty. When the
configuration sets `client_secret`, the first plan after the import shows one in-place update,
and the apply sends the secret from your configuration. When the configuration leaves
`client_secret` unset, Terraform cannot see a secret that the imported configuration stores,
and YugabyteDB Anywhere keeps authenticating with that secret until an apply changes
`client_id` or `tenant_id`.
