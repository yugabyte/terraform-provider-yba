# yba_runtime_config (Resource)

Sets a runtime configuration key on one scope in YugabyteDB Anywhere. The scope is the global scope, a customer, a provider or a universe.

Use the global scope (`00000000-0000-0000-0000-000000000000`, the default) for keys that apply to all of YBA, such as `yb.telemetry.allow_s3` or `yb.universe.metrics_export_enabled`. Set `scope` to a customer, provider or universe UUID to change a key on that scope only. YBA sets a key only on the scopes that the key supports: for example, it rejects a global key, such as `yb.telemetry.allow_s3`, on a universe. Destroying the resource removes the key from the scope. The scope then uses the value of a wider scope, or the default of the key.

~> **Note:** Only a Super Admin user can set or remove a key on the global scope.

~> **Security Note:** Set a secret key, such as `yb.security.ldap.ldap_service_account_password`, with `sensitive_value`, which Terraform hides in plan output. Terraform stores the value in the state file, so use a secure backend and restrict access to the state file. YBA masks the value of a secret key when it reads the key. When YBA returns the mask of the value in the state, Terraform keeps the value in the state.

## Example Usage

```terraform
# Allow the S3 exporter for telemetry providers. The global scope is the
# default.
resource "yba_runtime_config" "allow_s3" {
  key   = "yb.telemetry.allow_s3"
  value = "true"
}

# Turn on metrics export, so that you can create telemetry providers and
# export universe metrics to them.
resource "yba_runtime_config" "metrics_export_enabled" {
  key   = "yb.universe.metrics_export_enabled"
  value = "true"
}

# Every value is a string, whatever the type of the key. Write booleans,
# numbers, durations and lists as strings. YBA checks the value against the
# type of the key and stores it as written.
resource "yba_runtime_config" "task_gc_interval" {
  key   = "yb.taskGC.gc_check_interval" # a duration key
  value = "3 hours"
}

# A key on the scope of one universe: the protocol of the load balancer
# health checks for that universe.
resource "yba_runtime_config" "lb_health_check_protocol" {
  scope = yba_universe.main.id
  key   = "yb.universe.network_load_balancer.custom_health_check_protocol"
  value = "TCP"
}

# A secret key. YBA masks its value when it reads the key, and
# sensitive_value hides the value in plan output.
resource "yba_runtime_config" "ldap_service_account_password" {
  key             = "yb.security.ldap.ldap_service_account_password"
  sensitive_value = var.ldap_service_account_password
}
```

## Import

Runtime config keys can be imported using `<scope-uuid>/<key>`, or `<key>` alone
for the global scope:

```sh
terraform import yba_runtime_config.allow_s3 00000000-0000-0000-0000-000000000000/yb.telemetry.allow_s3
```

YugabyteDB Anywhere masks the value of a secret key, such as
`yb.security.ldap.ldap_service_account_password`, when it reads the key. Import writes that
mask to `sensitive_value`, so the first plan after the import shows one in-place update, and
the apply sets the value from your configuration.
