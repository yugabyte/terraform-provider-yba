# yba_aws_ear_config (Resource)

Manages a YugabyteDB Anywhere encryption-at-rest configuration that uses an AWS KMS key as the master key. YugabyteDB Anywhere uses the KMS key to wrap and unwrap the universe keys of each universe that uses the configuration.

Point the configuration at an existing symmetric KMS key with `cmk_id`, or let YugabyteDB Anywhere create one. Terraform does not manage or delete a key that YugabyteDB Anywhere creates.

There are two authentication modes. Set `access_key_id` and `secret_access_key`, or leave both unset to authenticate as the YugabyteDB Anywhere host through the AWS default credential chain, for example the instance profile on EC2. Without access keys, YugabyteDB Anywhere does not use `region`: the AWS SDK on the host selects the region, so the KMS key must be in that region. The identity needs `kms:DescribeKey`, `kms:GenerateDataKeyWithoutPlaintext`, `kms:Encrypt` and `kms:Decrypt` on the KMS key, which YugabyteDB Anywhere checks when it creates the configuration. YugabyteDB Anywhere also gives the KMS key an alias for each universe that uses it, which needs `kms:ListAliases`, `kms:CreateAlias`, `kms:UpdateAlias` and `kms:DeleteAlias`.

~> **Security Note:** `access_key_id` and `secret_access_key` are stored in the Terraform state file and marked sensitive. Use a secure state backend and restrict access to state files, or authenticate as the YugabyteDB Anywhere host, which keeps the keys out of Terraform.

~> **Note:** Only the arguments whose description says so can change in place. A change to any other argument forces replacement. YugabyteDB Anywhere does not delete a configuration that a universe has used: it keeps the universe's key history, also after encryption is disabled or the universe moves to another configuration, until the universe is deleted. A destroy of such a configuration fails, and the error names the universes. To move universes to a new configuration, create it, change `encryption_at_rest.kms_config_uuid` on each universe, and keep the old configuration (or remove it from state) until its universes are deleted. Give the new configuration `depends_on` on the old one, so that `terraform destroy` deletes the universe before the old configuration.

~> **Note:** Terraform refreshes `in_use` and the non-secret settings. YugabyteDB Anywhere masks credentials, so a credential changed outside Terraform, for example in the YugabyteDB Anywhere UI, does not show as drift. An apply without a change to the credential in the configuration does not send it again.

Use the configuration in a universe through its `encryption_at_rest` block. The
[Encryption at Rest](../guides/universe-edit-actions.md#encryption-at-rest) section of the
Universe Edit Actions guide describes how to enable encryption, rotate the master key or the
universe key, and disable encryption. For the YugabyteDB Anywhere side, see
[Create an AWS KMS configuration](https://docs.yugabyte.com/stable/yugabyte-platform/security/create-kms-config/aws-kms/).

## Example Usage

```terraform
# Encryption-at-rest configuration on an existing AWS KMS key, with access keys
# for authentication.
resource "yba_aws_ear_config" "access_keys" {
  name              = "aws-kms-prod"
  access_key_id     = var.kms_access_key_id
  secret_access_key = var.kms_secret_access_key
  region            = "us-west-2"
  cmk_id            = "arn:aws:kms:us-west-2:111122223333:key/1234abcd-12ab-34cd-56ef-1234567890ab"

  # Optional: a custom AWS KMS endpoint, for example a VPC endpoint.
  kms_endpoint = "https://vpce-0abc123-kms.kms.us-west-2.vpce.amazonaws.com"
}

# Authentication as the YugabyteDB Anywhere host (the instance profile on
# EC2): no access keys in Terraform or in state. The KMS key must be in the
# host's region. Without cmk_id, YugabyteDB Anywhere creates the KMS key.
resource "yba_aws_ear_config" "host_identity" {
  name   = "aws-kms-central"
  region = "us-east-1"
}

# A universe uses a configuration through its encryption_at_rest block:
#
#   encryption_at_rest {
#     enabled         = true
#     kms_config_uuid = yba_aws_ear_config.access_keys.uuid
#   }
#
# The yba_universe example shows a complete universe with the block.
```

## Schema

### Required

- `name` (String) Name of the configuration. Must be unique per customer. YugabyteDB Anywhere cannot rename a configuration, so a change forces replacement.
- `region` (String) AWS region of the KMS key, for example `us-west-2`. Used only with access keys. A change forces replacement.

### Optional

- `access_key_id` (String, Sensitive) AWS access key ID. Set it with `secret_access_key`, or leave both unset to authenticate as the YugabyteDB Anywhere host. Can change in place: YugabyteDB Anywhere first checks that the new credentials can decrypt the active universe key of each universe that uses the configuration.
- `cmk_id` (String) Key ID or key ARN of an existing symmetric KMS key. This key is the master key. When not set, YugabyteDB Anywhere creates a KMS key with a key policy for the account root and the configured identity, and this attribute returns its key ID. To check the credentials first, it also creates a test key and schedules its deletion. A change forces replacement.
- `kms_endpoint` (String) Custom AWS KMS endpoint, for example a VPC endpoint. A value without a scheme uses HTTPS. Requires access keys. Can change in place.
- `secret_access_key` (String, Sensitive) AWS secret access key for `access_key_id`. Can change in place, together with `access_key_id`.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `id` (String) The ID of this resource.
- `in_use` (Boolean) Whether a universe holds key history for this configuration. A configuration in use cannot be deleted.
- `uuid` (String) UUID of the configuration.

## Import

Import an AWS KMS configuration with its UUID. The `yba_ear_config` data source returns the
UUID for a configuration name:

```sh
terraform import yba_aws_ear_config.access_keys <config-uuid>
```

Import fails for a configuration of another KMS provider, and the error names that provider.
YugabyteDB Anywhere never returns `access_key_id` or `secret_access_key`, so they stay empty
after import. When the configuration sets them, the first apply sends the keys again. When the
configuration leaves them unset, Terraform cannot see access keys that the imported
configuration stores, and YugabyteDB Anywhere keeps authenticating with those keys. To make
YugabyteDB Anywhere authenticate as its host, set `access_key_id` and `secret_access_key` to a
valid key pair and apply, then remove both and apply again. YugabyteDB Anywhere checks the
keys with AWS before it accepts the first edit, so the key pair must be valid.
